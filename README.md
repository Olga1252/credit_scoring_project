# Credit Scoring Project 

Данный проект включает в себя выполнение задания ,в котором был реализован сквозной автоматизированный пайплайн разработки, тестирования ,развертывания и мониторинга модели машинного обучения для пресказания вероятности дефолта клиента по кредитной карте в следующем месяце  . 

# Датасет

Был использован датасет Default of Credit Card Clients Dataset с UCI Machine Learning Repository, 
включающий в себя 30 000 клиентов  , 23 исходных признака , идетификатор и целевая переменная. 

Целевая переменная: default.payment.next.month
- 0 - отсутствие дефолта
-1- дефолт 

Данные были разделенены на обучающую и тестовую выборки: 
- train - 24 000 клиентов 
-test - 6 000 клиентов 
- стратификация по целевой переменной 
- random state = 42 

Разведочный анализ: notebooks/01_eda

## Подготовка и проверка данных 

Валидация перед разделением 

- наличие обязательных столбцов; 
- проверяются ли числовые типы;
- Great Expectations проверят пропуски;
- диапазон возраста;
- проверяются допустимые значения целевой. 

Feature Engineering добавляет признаки: 

BIL_AMT_SUM |Сумма счетов за 6 месяцев 
PAY_AMT_SUM | Сумма платежей за 6 месяцев
BILL_AMT_MEAN | Средняя сумма счёта
PAY_AMT_MEAN | Средняя сумма платежа
NUM_DELAYED_PAYMENTS | Кол-во месяцев с положительным кодов задержки 
BILL_TO_LIMIT_RATIO | Отношение суммы счетов к кредитному лимиту

## Получение данных и воспроизведение обучения

Исходный файл должен находиться по пути:

text
data/raw/UCI_Credit_Card.csv

Ожидается CSV-версия датасета с колонками `ID`, `LIMIT_BAL`, `SEX`, `EDUCATION`, `MARRIAGE`, `AGE`, `PAY_0`, `PAY_2`–`PAY_6`, `BILL_AMT1`–`BILL_AMT6`, `PAY_AMT1`–`PAY_AMT6` и `default.payment.next.month`.

Ограничение:
DVC remote не настроен. Исходные данные и модель находятся в локальном DVC-кэше и не скачиваются при `git clone`. Для запуска на другом компьютере необходимо отдельно получить исходный CSV и поместить его по указанному пути. Для точного воспроизведения нужна та же версия исходного файла.

После установки зависимостей и получения данных активируйте окружение и запустите:

powershell
dvc repro
dvc status


DVC-пайплайн содержит два этапа:

prepare — валидация и разделение данных;
train — подбор параметров, обучение, оценка и сохранение модели.

Модель сохраняется в:

text
models/trained/model.joblib

Повторный dvc repro при неизменных зависимостях пропускает выполненные этапы.

Для принудительного повторного выполнения:

powershell
dvc repro --force

Каждый фактический запуск обучения также создаёт новые записи MLflow.

## MLflow

Эксперимент называется `credit_scoring_project`.

При обучении сохраняются:

- параметры и средние CV-метрики каждой из восьми конфигураций;
- параметры лучшей модели;
- тестовые метрики;

- обученная модель через `mlflow.sklearn.log_model`.

powershell

Интерфейс: http://127.0.0.1:5000

База `mlflow.db` и артефакты экспериментов создаются локально при обучении.

## Мониторинг распределений признаков

При работающем контейнере на порту 8001:

powershell
python -m src.monitoring.simulate_requests
python -m src.monitoring.check_drift

Первый скрипт отправляет 500 клиентов из тестовой выборки в API и сохраняет признаки, целевую переменную и предсказания.

Второй скрипт сравнивает распределения 23 исходных признаков с обучающей выборкой через PSI.

Для числовых признаков границы интервалов рассчитываются по обучающим данным. Для категориальных сравниваются доли категорий. Для пустых интервалов применяется сглаживание.

Условные пороги учебного отчёта:

| Менее 0.1 | `stable` 
| От 0.1 до 0.25 | `check`
| От 0.25 | `drift`

В выполненной симуляции все 23 признака получили статус stable.

Это ожидаемо для случайной подвыборки из того же исходного датасета. Отсутствие сигнала PSI не доказывает сохранение качества модели: PSI оценивает распределения входных признаков.

Мониторинг запускается вручную и не включает автоматическое переобучение.

## Тестирование и CI

Локальные проверки:

powershell
python -m black --check src tests
python -m flake8 src tests
python -m pytest -q

Для исправления форматирования:
powershell
python -m black src tests


Набор содержит 14 тестовых случаев:

- валидация данных;
- отклонение некорректного возраста в API;
- формат успешного ответа API;
- расчёт дополнительных признаков;
- сохранность исходной таблицы;
- обработка неположительного кредитного лимита;
- PSI для одинаковых и изменённых распределений.

API-тесты используют mock модели и не требуют обученного файла.

GitHub Actions при push и pull request выполняет:

1. установку и проверку зависимостей;
2. проверку Black;
3. проверку flake8;
4. pytest;
5. валидацию образца данных через Great Expectations.

Для CI используется `tests/data/credit_sample.csv`. Полная исходная выборка проверяется при выполнении этапа prepare.

## Ограничения

Проект демонстрирует учебный MLOps-процесс и не предназначен для принятия реальных кредитных решений.

- Датасет исторический и относится к определённой популяции клиентов.
- Порог классификации 0.5 не оптимизирован под стоимость ошибок.
- При текущем пороге Recall на тестовой выборке составляет около 0.34.
- Отдельная проверка калибровки вероятностей и справедливости модели не выполнена.
- DVC remote и автоматическое развёртывание не настроены.
- Работа API в Docker проверена локально.
